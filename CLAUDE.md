# Stargazer

A single-file web page (`site/index.html`, no build step, no dependencies) that shows saved Reddit posts as a bento gallery.
Hosted on GitHub Pages. Accounts and storage come from Supabase (free plan). The page is public; the data is not.

## Layout
- `README.md`  user-facing (what Stargazer is, quick start, local use, standalone download). Keep it free of deploy instructions; those live in `docs/SELF-HOSTING.md`. Keep its feature and privacy claims true when behaviour changes.
- `site/index.html`  the whole app (HTML, CSS, JS). `site/config.js` holds the Supabase URL and anon key (safe to publish; Row Level Security protects data).
- `supabase/schema.sql`  table, row-level security and the `merge_posts` function. Run once in the Supabase SQL editor.
- `supabase/functions/redgifs/index.ts`  optional Edge Function (deployed by hand, Verify JWT off): looks RedGifs clips up for the page when the browser cannot reach the RedGifs API ("Failed to fetch"). The page tries RedGifs directly first, then this helper.
- `tools/screenshots/`  regenerates `docs/screenshots/*.jpg` for the README from invented posts and generated artwork (`make_images.py`, then `shoot.py`). Re-run after visible UI changes. Never use real posts or accounts.
- `tools/hot_relay.py`  optional local relay that lets the page read Reddit's real hot feed (browsers cannot call Reddit directly).
- `.github/workflows/`  `pages.yml` deploys `site/`; `keepalive.yml` pings Supabase so the free project is not paused.
- `tests/`  Playwright checks (`merge_test.py`, `nsfw_test.py`, `panels_test.py`, `lists_test.py`, `reset_test.py`, `viewer_yt_test.py`, `wayback_test.py`, `gone_pic_test.py`, `audio_test.py`, `unload_test.py`, `cloud_reload_test.py`, `first_load_test.py`, `stats_test.py`, `intro_test.py`, `nav_test.py`, `view_test.py`, `sound_follow_test.py`, `layout_test.py`, `merge_prompt_test.py`, `localmeta_test.py`, `imgpause_test.py`, `rg_embed_test.py`, `polish_test.py`, `regrab_test.py`, `review_test.py`, `header_test.py`, `tilesize_test.py`, `seenimg_test.py`, `sort_test.py`, `links_test.py`, `reader_test.py`, `status_clear_test.py`, `signout_others_test.py`, `subsel_test.py`, `nsfwcount_test.py`, `rg_helper_err_test.py`, `reveal_touch_test.py`, `texttitle_test.py`, `listtext_test.py`, `uxpass_test.py`, `rgviewer_test.py`, `autoplayall_test.py`, `ctlfit_test.py`, `touchpin_test.py`, `layer_test.py`, `prefs_test.py`, `uxfix_test.py`, `trayrow_test.py`, `gifstill_test.py`, `focusplay_test.py`, `sources_test.py`, `subfeed_test.py`, `archive_err_test.py`, `viewtap_test.py`, `viewland_test.py`, `rggone_test.py`, `recplay_test.py`, `fullw_test.py`, `viewfill_test.py`, `lensort_test.py`, `rgsplit_test.py`, `onecol_test.py`, `tapseek_test.py`, `speed_test.py`, `pullsync_test.py`, `longsess_test.py`, `look_test.py`, `sheets_test.py`).

## Rules that must not be broken
1. **No personal data in the repo.** No saved-post lists, no CSV files, no subreddit lists from a real account, no keys other than the Supabase anon key. `.gitignore` blocks `*.csv` and `local/`.
2. **Never add the Supabase `service_role` key anywhere.**
3. **Data scheme** (CSV and database): `id, permalink, starred, updated, deleted`. `updated` is the ms time of the last change to that post; `deleted=1` is a tombstone that is kept forever.
   Merge rule, in `pickRec` / `mergeSets` in the page and in `merge_posts` in SQL (keep them identical): newer `updated` wins; on a tie a tombstone beats a live row; two live ties keep the star if either has it.
   A post with a tombstone must never be revived by an older copy.
   A manual NSFW override is stored in the permalink as `?nsfw=1` / `?nsfw=0` (see `nsfwMark`, `toggleNsfw`); no mark means the automatic guess. Keep it in the permalink so the columns and the database schema do not change.
4. Every edit must stamp the record (`nowT`) and call `markDirty`; deletions go through `deleteRows`.
5. The page must keep working with no `config.js` values (accounts hidden) and from `file://`.

## Working notes
- The top bar has three floating panels: **Display** (`#viewpanel`, `#viewtoggle`: how things look), **Filters** (`#panel`, what is shown) and **Source** (`#srcpanel`, which list, sign-in, sync, Subreddit mode). Opening one closes the others (`openPanel`; body classes `view-collapsed`, `deck-collapsed`, `src-collapsed`). Keep source/account controls out of Filters, and view settings out of both. Each panel (and `#toast`) is a `popover="manual"` in the top layer: our own code shows and hides them, because the browser's light dismiss would also close a panel when its confirm dialog or an Undo toast appears. On desktop a panel is `position:fixed` under the bar (`--deckb`) with its right edge under the nav buttons (`--panr`, measured from the buttons since `#navbtns` is `display:contents`). Phone sheets drag down to close from the handle or any plain part while scrolled to the top (past 30% or a flick over 0.11px/ms; otherwise they spring back). Opening a panel clears a passing (non-Undo) toast, and each toast is raised above an open sheet (`sheets_test.py`). The Source switch and list tools come first in the Source panel; the Account block (sign-in, marked Optional) follows as a folded section, then Advanced (RedGifs helper status). A list is either **Local** (this browser or a linked file) or **Account** (`rec.cloud`, synced); `csvInfo` shows which, and `#csvCloud` switches it.
- Navigation: `#navbtns` holds Source, Display, Filters, Shuffle and Search. On wide screens it is `display:contents` inside the top bar (labelled buttons, search box always visible); on phones it is a fixed bottom bar and the panels open as bottom sheets. The top bar loses its `backdrop-filter` on phones because a blurred parent would trap fixed children.
- The Active / Loaded / Total strip lives in the top bar; on phones it sits right-aligned beside the logo (number over label, 12.3k style for big counts; with nothing filtered and nothing still loading it shows one number labelled Posts, `body.stats-flat`). A refresh keeps filters and scroll for the tab (sessionStorage only; NSFW never persists to a later visit).
- The **Display** panel holds Layout, Columns (the tile size slider in Masonry/Grid; List's own 1 / 2 / 3 / Auto choice in List), Full width, Card info & controls, Auto-play and Theme. The **Filters** panel has **Filter and sort** (Sort, Time range, Subreddit, NSFW, Show text posts, Starred only, Hide broken media) and Browse chips, then Shortcuts. (Before Nov 2026 the view settings were a View column inside Filters.)
- Layouts (first in the Filters panel's View section, `LAYOUT` / `layoutCard` / `paintLayout`): **Masonry** (default, best for media), **Grid** (equal squares) and **List** (short rows on a solid surface with a small square thumbnail on the left and the text beside it, purple/magenta accents, no playback or media controls, card info always shown; the Card info & controls setting does not apply there).
- The page is one file on purpose. Search by function name (`syncCloud`, `mergeSets`, `fillCard`, `openViewer`, ...).
- Never show a person an archive's raw API/JSON address (`isApiUrl`), and do not link to Reveddit (it depends on Reddit's closed API and just errors). Posts recovered from Arctic Shift or PullPush open in the built-in reader (`openReader`, `hasReader`: title, author, score, saved text `m.x`, and comments loaded on request from Arctic Shift's comments search); Wayback-recovered posts link straight to their snapshot (`m.wb`); anything else gets the Wayback address (`wbPostHref`). The comment count and the Comments button always go to the Reddit page first (the thread is often still there, even for removed posts); the reader only offers loading comments from the archive as a fallback.
- Status text (`loadText`, `recText`, progress bar) belongs to one list: `clearStatus()` runs from `resetView` (every list change, unload, sign-out) and the recovery's `status()` ignores writes from a stale run (`gen!==loadGen`).
- Preview loading (`fetchBatch`, `askSource`) sends only base-36 ids; a 400 for a batch is retried once as four smaller pieces (never split further, so a refusing archive is not flooded); when every archive fails the message lists each one's answer ("Arctic Shift: could not connect; PullPush: HTTP 400"), not just the last (`archive_err_test.py`).
- Archive APIs (Arctic Shift, PullPush, Wayback) are rate limited; requests go through `timed()` / `apiRetry()` with per-host spacing and back-off. Do not add direct `fetch` calls to them.
- A tile never shows a playing GIF by itself: an animated file (`isAnimUrl`: any `.gif` address, **including Reddit's own `external-preview.redd.it/NAME.gif?format=png8` copies, which are animated GIFs**, and `format=mp4`) is ordered after every still candidate in `imgCandidates`, and if it is the picture that loaded it is frozen on its first frame (`freezeFrame`, a `canvas.still`). Hover / in-view play and the viewer still use the real file (`gifstill_test.py`).
- **Imgur answers `ID.jpg` for a video / GIF post with the moving file itself** (the tile `<img src="https://i.imgur.com/ID.jpg">` played on its own, with no `<video>` anywhere), so `mayMove(url,p)` also freezes an imgur picture on a `gif` / `video` post (`gifstill_test.py`); the same helper runs in the tile loader and in `rescue`. `isMp4Fmt` covers both `format=mp4` and Reddit's `fm=mp4` (g.redditmedia.com).
- **Play sources** (`playSources`): a post that links straight at a video file (imgur `NAME.mp4`) plays from that file first (https), then Reddit's own mp4 preview (`m.v`, e.g. `g.redditmedia.com/NAME.gif?fm=mp4`), then the DASH files. A source that fails hands over to the next one, both in the tile (`startPlay` error handler) and in the viewer (`vlist`). Before this, a post whose preview address came first never played if that address failed (`sources_test.py`, needs ffmpeg).
- **Recovered posts play like any other card** (`recplay_test.py`): `playSources` adds `i.imgur.com/ID.mp4` for an imgur GIF / video post linked as a page, and, last of all, the Wayback Machine's raw copy (`wbVid`, `id_`) of every imgur / i.redd.it / RedGifs clip file, so a clip whose host purged it still plays (the card's `data-vc` holds up to 11 fallbacks). When the tile's picture that loaded is an animated `.gif` (often only an archived copy survives) and the post has no clip, that GIF becomes the card's clip (`data-v`, wired for hover / in-view play). A card's source chain that reaches a `.gif` restarts as an `<img>` clip instead of feeding it to a `<video>`.
- Reddit's mp4 copy of a GIF is named `NAME.gif?format=mp4`: it is a video (`isMp4Fmt`, `isGifFile`, `vtype`), never a picture, because an `<img>` holding an mp4 plays by itself in Safari. Tile stills (`video.still`) re-pause themselves if anything starts them (`startStill`).
- **Auto-play group** (Filters, View) has exactly two toggles. **Autoplay active card** (`#autohover`, `auto.hover`, `saved-posts-autoplayhover`, default on): the card under the pointer or with keyboard focus plays, and on touch the card in focus (`focused`, `pickFocus`) plays; off means nothing plays unless started by hand. **Autoplay all media in viewport** (`#autoplayall`, `auto.all`, off by default, standing warning line): every clip and embed on screen plays with no cap (YouTube/RedGifs and touch included) and stops when it leaves the screen. The old capped "Auto-play in view" (`MAX_AUTO`) was removed on request; do not bring it back. `syncPlay` reads hover through `hv`.
- With both Autoplay toggles off, a double tap / double click on a still clip tile starts it by hand (`t._manual`, honoured in `syncPlay`, cleared when the tile leaves the screen); only in that state does a single tap on a clip tile wait 360ms for a second tap, so taps stay instant otherwise. The `#apwarn` note is muted while all-media is off and takes the warning colour when it is on.
- With Autoplay active card on (and all-media off) a clip plays only while its card is hovered or has **keyboard** focus (`wirePlayable`: `focusin` counts only when the target is `:focus-visible`). A mouse click leaves focus on the tile's link but must not keep the clip playing after the pointer moves away (`focusplay_test.py`).
- **Thumbnail order** (`imgCandidates`): Reddit's own preview (`m.th`) is always asked for first, even when it is an animated `.gif` copy (it is small and gets frozen). Full-size moving files (an original `.gif`, imgur's `ID.jpg` on a GIF/video post, which is the whole animated file) go last; putting them first held the image queue for seconds per tile and every thumbnail waited (`gifstill_test.py`). In full screen a video fills the stage (`width/height:100%; object-fit:contain`), so a 480p clip scales up like the browser's own full screen.
- Images load through the `IMGQ` queue (limits concurrency, pauses on bursts of failures, shows a countdown). Pictures that loaded before (`SEEN`, short hashes in `saved-posts-seenimg`) skip the queue's pacing so a refresh shows them at once from the browser cache.
- **Loading speed** (`speed_test.py`): `IMGQ` runs up to 8 loads; a job whose first address is on Reddit's or YouTube's CDN (`FASTIMG`: redd.it, redditmedia.com, ytimg.com) starts 25-70ms after the last one, every other host (imgur, archives, mirrors) keeps the 180-430ms spacing, and after a pushback (`IMGQ.strikes`) everything is slow again until it decays. `nextJob` drops jobs whose card is gone (no slot, no gap spent) and takes on-screen cards (`cardView`) first. `loadAll` asks the archive for the posts on the page first (`list` order), in a first batch of 30, then 100s with a 200ms breather, and writes the cache at most every 4s plus at the end. The preview cache (`saved-posts-meta-v7`) lasts 30 days after the last save; when it no longer fits localStorage it moves to IndexedDB (`kv` key `meta-cache`, flag `saved-posts-meta-idb`, read once by `loadIdbMeta` when loading starts). Geist (Latin subset, variable) is embedded as a `data:` font in the page, so there is no font service request and it works from `file://`. **Long sessions** (`longsess_test.py`): cards have `content-visibility:auto` (off-screen cards skip style, layout and paint); `farIO` lets cards more than about three screens away drop their picture / video still address (kept in `data-far`, put back on approach); `refresh` keeps the cards already on the page when they are still the head of the new list, and `metaRefresh` re-filters at most every 1.2s while previews stream in. `fetchBatch` asks Arctic Shift first and also PullPush if Arctic Shift has not answered within `HEDGE_MS` (2.5s) or failed; the first good answer wins and the other fills its gaps.
- On touch screens Show on hover / focus means the tile in focus (`.is-focus`) shows its layer; Show always shows all.
- Touch screens use touch events for pinch/zoom in the viewer; mouse and pen use pointer events. A text-only post (`.is-text`) has no picture to say what it is, so while its layer is down it keeps just its title on the tile (`.peek`), on a lavender tile (`--lav`) with a faint picture mark instead of words.
- Test by loading the page in Playwright with network routes mocked (see `tests/`). There is no live access to Reddit or the archives from the dev sandbox.

- Deleting a single post (or several, via **Bulk Actions** mode) has no confirm for single deletes: it shows a toast with **Undo** (`toast(msg, {label, fn})`, `restoreRows`). Bulk delete asks once, then also offers Undo. Selection mode (`SEL`, `selMode`, `selAct`) acts on `list`; its action bar `#selbar` lives inside `.deck`: on desktop a tinted strip under the top bar, on phones a fixed bottom sheet; NSFW changes go through `markNsfw` (no commit) so many posts commit once.
- What is remembered: tab-only (sessionStorage, `saved-posts-view`) are filters, search, subreddit, range, scroll; browser-wide (localStorage) are Theme, Layout (per list), List columns, Card info & controls, Auto-play options, volume, **tile size** (`saved-posts-tile-cols` desktop tiles across (an older `saved-posts-tile` px value carries over, 370 = one across), `saved-posts-tile-phonecols` phone tiles across), Full width (`saved-posts-fullwidth`, its own tile size in `saved-posts-tile-fullw`), full screen Fit / Fill (`saved-posts-viewfill`) and per-list **sort, Starred only, Show text posts once toggled** (`saved-posts-listprefs`, `saveListPrefs` / `applyListPrefs`, applied in `startCsvMode`). NSFW and search text never persist to a later visit.
- A CSV or account list opens sorted **Newest posts** (set in `startCsvMode`; Saved order stays in the Sort menu); Subreddit mode opens on Hot. The Filters badge counts only settings changed from the defaults. Theme lives in the Display panel (it is about how things look, not which list). Layout is remembered per list (`saved-posts-layouts`, `applyListLayout`) with the global value as the default.
- The Subreddit dropdown (`#subsel`) is rebuilt by `buildSubs()` from `refresh()` whenever the list or chosen subreddit changes; a subreddit name on a card filters the list (tooltip, hover underline, toast with Show all; clicking the same name again clears it), it never opens Reddit. The filter is shown in the search box as an `r/name` word (`boxText`, `syncBox`, `setSub`); typing or deleting that word changes the filter, anything else in the box is the text search. `state.sub` can hold several subreddits joined with `+` (typed as `r/a+b` or `a+b`, every name must be in the list; `subIn` does the matching).
- The viewer has previous/next **post** navigation (`viewerPost`, Up/Down or Left/Right arrows, swipes, bottom buttons) separate from the gallery's image arrows. On touch, **swipe up = next post, swipe down = previous** (`swipeStep`; mostly vertical, over 70px), on pictures and on clips; sideways moves through a gallery's pictures, or between posts elsewhere. On a clip the touches are only watched (passive), so a tap still reaches the video for the player bar and a swipe cancels it. Embedded players (YouTube, RedGifs' iframe) keep their own touches, which is why the buttons stay. Swipe down no longer closes full screen (the ✕, the exit button and Back do) (`viewtap_test.py`). **Slide transition** (`slideTo`, `dragFollow`, `dragEnd`, `SLIDE`): the post follows the finger vertically (damped where there is no post that way); past 70px, or a quick flick (over 24px at more than 0.35px/ms), the post moves into a ghost copy (`.vghost`, a clip in it paused on its frame) that slides away while the stage loads the next post and slides in from the opposite edge together (320ms, `cubic-bezier(.32,.72,0,1)`); otherwise it springs back. The Previous / Next buttons slide too; keyboard steps stay instant; reduced motion skips the slide. Only the stage moves, the bar and buttons stay put.

- User-facing wording says **NSFW** (the Filters panel carries live counts beside NSFW and Show text posts, `#nsfwcount` and `#textcount`, set in `updateChips`); the card toggle shows it stacked on two lines (NS over FW). The filter modes are Hide / Blur / Show / Only. In Blur mode a mouse hover unblurs a tile (`@media (hover:hover)` only, because a tap leaves a touch card "hovered"); on touch the Reveal/Blur button toggles `.show` and remembers the post in `REVEALED`, so a card rebuild (`fillCard`) keeps it revealed; changing the NSFW mode clears it.
- List on desktop has a **Columns** choice (1 / 2 / 3 / Auto, `LCOLS`, `paintCols`, remembered in `saved-posts-listcols`); a fixed count also caps each column's width so rows stay easy to scan. Default is Auto. Desktop List uses a 20px column gutter (`--lgap`) against the 6px row gap; row spans are computed from the row gap, so leave that alone.
- **Show text posts** defaults to on in List and off in Masonry/Grid (`textDefault`, `applyTextDefault`) until the person toggles it (`textTouched`, kept in the tab's view state); the Layout hint (`paintLayoutHint`) adds a "Text posts default to off in this view" note under Masonry/Grid while text posts are off.
- The Source panel always shows a loud "Last pulled from Reddit" line under the list blurb (`#pullLine`, set in `updateMergeHint` from `saved-posts-lastmerge`; Reddit's export has no date inside, so the date is the file's modified time (`pullTime`) when a raw Reddit CSV is opened or merged; a file this page wrote (has an `updated` column) says nothing, so such a list shows "date unknown" with its first-opened date; the next raw Reddit CSV opened or merged sets it. There is deliberately no manual date control). For an **Account list** the date also lives in the account (the user's own auth metadata, `user_metadata.sg_pulled`, set with `PUT /auth/v1/user`; no table or schema change): `acctPull` runs after every good `syncCloud` and after `noteMerge`, the newer real date wins on both sides, a guessed (`est`) date is never uploaded, and a failure is silent (`pullsync_test.py`). Before this, a merge on one device left every other device showing the old date and the merge prompt. Over 30 days it turns red and the merge prompt (`#mrgHint`, Reddit data-request link, Merge CSV, Remind me later) shows too.
- Source panel order: list picker, then the list's facts (`.listfacts`: count blurb, Local/Account note, last pulled; plain muted text, not pills, because they are not controls), then at most one warning (the stale-pull prompt `#mrgHint` wins over the backup hint `#expHint`), then the actions. Pills and fills are for things you can press; warnings alone get colour boxes. The Saved CSV / Subreddit switch (`#srcpanel .srcseg`; the Layout, Columns and NSFW switches share the `.srcseg` class but keep the filled accent) shows the chosen side as a quiet raised tab (`--seg-on`, ink text), not the accent fill, so **Open CSV** is the one filled action in the panel. A dot on the Source button (`data-attn`, `updateSrcDot`) shows when a warning is waiting inside the closed panel. With no list, Shuffle is disabled (`.no-data`); the first-run screen reads pitch, then steps, then Open CSV. Phone sheets have a handle and scroll shadows.
- Card buttons: the bookmark (`.save`) means "in your list" and removes the post (label "In your list: tap to remove"; the first removal's toast also explains it); a starred card gets a white filled star; the media label (`.badge.media`) is plain text, since only the buttons are controls.
- Unloading the last list leaves an empty placeholder list (`builtin-*`); `isEmptySlot` makes the selector say "No source loaded", the blurb say so, and hides the Local/Account note.
- While previews load, a small magenta dot (`.loaddot`, before `#loadText`) breathes and sends out a soft ring (`dotbreathe`, `dotring`: scale and opacity only, so it stays smooth); it exists only while `body.previews-loading` is set (so the text is flush left otherwise), is centred on the text line (`.load` aligns items centre) and fades in.
- **Full-screen player** (`viewerControls`, `.vctl`, `ctlHtml` shared with the cards): every video in the viewer plays with our own bar (play / pause, scrubber, time, speaker with the volume flyout, and an exit-full-screen button `.vfs` at the right end that closes the viewer like the ✕; `has-sound` only when the clip has sound), never the browser's `controls`. The bar sits above the previous/next post buttons, uses the tray's glass, and fades with them while a clip plays untouched (`vidle`, `viewerWake`, 2.6s; mouse movement, a tap or a key brings it back; keyboard focus inside keeps it up). A tap or click on the clip plays / pauses at once and brings the bar up (`viewerTap`); a second tap within 320ms (`VTAP_MS`) on the right half of the screen undoes that and jumps 10s forward, on the left half 10s back (`viewerSeek`, `VSEEK`), and each further quick tap adds another 10s, with a round mark (`.vseek`) on that side showing the total (`tapseek_test.py`, `viewtap_test.py`). The bar hides on its own while playing (there is no tap to hide it any more). Space or K plays / pauses (even with the close button focused), M mutes. **RedGifs posts play the same file the card uses** (`vlist`, e.g. `media.redgifs.com/NAME.mp4` from the embed name) in this player; RedGifs' own iframe (`rgEmbed`) is only the fallback when there is no file or every file fails, because its own full-screen button could not be reached from ours (`audio_test.py`).
- **Leaving full screen after moving on** (`landOn`, `VIEW.first`): if the post showing last is not the one full screen opened on, the feed renders down to it, centres its card, focuses it and pins it as the touch focus card; two later passes re-centre only if leaving full screen or the history step moved the page (they never fight the person's own scrolling). Closing on the same post keeps the page where it was (`viewland_test.py`).
- **A post that will not load never ends full screen** (`viewerFail`, `VIEW.dir`): while moving through posts it is skipped in the same direction with a short toast; opened directly it shows "Nothing to show for this post." in place, and the buttons and swipes keep working (`viewland_test.py`).
- **Deleted RedGifs clips** (`rgFilesGone`): when every file of a RedGifs post fails and RedGifs itself has not vouched for the clip (`!m.rgDone`), one no-cors `HEAD` to the file decides: any answer (a 404 comes back opaque) means the file is gone, so the post is marked `rgGone` (broken media: hidden by Hide broken media, counted as dead) and full screen says "This clip has been removed from RedGifs." instead of RedGifs' "Error loading this gif" player; a request that gets no answer is a network problem and falls back to RedGifs' player. The tile's player does the same check when its last file fails (`rggone_test.py`).
- **Fit / Fill in full screen** (`.vfill`, top left of the viewer, `setViewFill`, `VFILL`, class `vcover` on `#viewer`, `saved-posts-viewfill`, key F): Fit shows the whole picture or clip (`object-fit:contain`, the default); Fill fills the screen and crops what does not fit (`cover`). It applies to pictures and clips, carries on from post to post and is remembered for the browser; the button hides over YouTube, RedGifs' own player and messages (`viewfill_test.py`).
- **RedGifs in full screen opens the HD file** (`rgHdList`, `rgHd`): RedGifs names a clip's files `NAME.mp4` (HD) and `NAME-mobile.mp4` (SD). The card keeps the lighter SD file for silent clips; full screen tries `m.vh` (RedGifs' own HD address), then the SD address with `-mobile` dropped, then the embed name (`m.g`), and only then the card's sources, so a missing HD file falls back to SD (`viewfill_test.py`) RedGifs signs its file addresses for one visitor (address and browser) and they run out (`expires=`), so a kept address can fail later and used to drop full screen onto RedGifs' own player, which starts in SD: `rgStale` skips run-out addresses in the cache and in `rgNeeds`, and when every file of a RedGifs post fails, full screen looks the clip up once more (`opts.rgFresh`) and replays it in our player before `rgLast` falls back to RedGifs' player. `rgHd` never invents an HD name for a signed address. RedGifs' iframe has no setting to start in HD (userscripts like RedGifs-AutoHD do it by rewriting RedGifs' own API replies inside redgifs.com, which a page cannot do across origins), so the cure is keeping our own player.
- **A refused RedGifs list lookup is split** (`rgFetchMany`, `rgLookup`, `rgIs404`): RedGifs answers `/v2/gifs?ids=` with 404 (through the helper: "helper 502: gifs 404") when one clip in the list was deleted, and then says nothing about the others, so every clip in that batch used to fall back to RedGifs' own SD player. The list is now split in halves until the missing clips stand alone; the rest get their real files. A clip refused on its own is marked gone only if another lookup in the same run worked, so a RedGifs outage never marks everything deleted (`rgsplit_test.py`). The helper (v2, its reply carries `v:2`) does the same on its side: a list refused with 404 is retried without the visitor's address and browser, then clip by clip (`/v2/gifs/{id}`, five at a time), and it reports `missing`; it also passes `duration` through. It is deployed by hand, so changes to it only take effect after a redeploy. The Advanced line counts clips found and deleted this visit (`RG_N`) beside the last problem.
- **Sort by clip length** (`long` = Longest clips, `short` = Shortest clips, `byLen` in `sorted`): the length is `m.d` in seconds, from Reddit's `reddit_video` / `reddit_video_preview` `duration` (`slim`), RedGifs' `duration` (`rgShape`, `rgApply`), or from any clip that loads in a tile or full screen (a capturing `loadedmetadata` listener; the feed is not re-sorted on the spot). Posts with no known length (pictures, text, links, clips not looked at yet) go last in both directions (`lensort_test.py`).
- In the viewer, RedGifs' own player (`iframe.vrg`, the fallback when there is no clip file to play) has its controls along the bottom, so the stage gives up a band for the previous/next post buttons (`.vstage:has(iframe.vrg)`) rather than letting them sit on the scrubber.
- **Card info & controls** (`#cardmode`; `cm-collapsed` / `cm-hover` / `cm-always` on the body, `saved-posts-cardmode`, an old `saved-posts-ctlmode` carries over) is the one setting for what a Masonry/Grid tile shows beyond its media. Each card has one glass **layer** (`.layer`: the info block, the Source and Comments buttons (`.actions`), the action pill `.lay-cap` (NSFW / star / bookmark / full screen), and `.lay-play` where `buildControls` puts the player controls). Collapsed: media only, with a faint handle (`.lhandle`, lower part of the tile) that opens that card's layer (`setLayer`, class `.lay-open`; the grabber `.lh-close` at the layer's top closes it; swipe up on the handle opens, I toggles the hovered / focused card, Esc, a tap elsewhere, opening another card, or scrolling the card out of view closes it). Show on hover / focus: the layer rises with the pointer (the focused tile on touch). In every mode the layer can be put away by hand (`toggleLayer`, `layerUp`, class `.lay-shut`): tap the tile, tap or swipe down the grabber, or press I; the handle comes back to raise it again. A hand-shut card stays shut until it is tapped or its handle used (Show on hover / focus also clears it when the pointer or focus leaves the card; a mode change clears all). Show always: up on every card. The badges and placeholder label follow the layer. In List the layer boxes are `display:contents`, so the row keeps its own arrangement (info text and round buttons positioned on the card, setting row hidden). Closed layers must not catch taps (`.layer *` inherits `pointer-events`). Tiles narrower than 300 / 200 / 140px (container queries on `.card`) condense the layer (smaller buttons, one-line title, no meta). There is no hairline progress or bare player bar on a tile any more (`ctlfit_test.py`, `layer_test.py`).
- In Masonry / Grid a plain click or tap on a tile toggles its layer (`a.thumb` click handler in the grid listener) instead of opening the post; the **Open post** button in the layer (first, then Comments; it goes to the post, and is not the top bar's Source, which is the list; the pill on the right in the order NSFW, Favourite, Saved, Full screen) goes to the post, and modifier-clicks and List keep the plain link. Double tap (or double click) on a tile that has player controls pauses or resumes it (`pp.click()`); a single tap on those toggles the layer **at once** (it used to wait 360ms, which felt slow); if a second tap comes within 360ms (`card._tapT`) the layer goes back to how it was (`card._tapWas`) and the clip pauses / resumes. During that window the card has `.tap-wait`, so its layer and handle let the second tap through to the tile instead of a tray button (`tapseek_test.py`). On the narrowest tiles (<=140px) the layer drops the title, Comments and the NSFW button so it still fits.
- The handle and grabber are small centred targets (72px wide) with `touch-action:none`, and the scrubber has `touch-action:pan-y`, so a scroll that starts on a tile or tray scrolls the page instead of opening the tray or scrubbing. Sound control on a clip (`.volwrap` in the player controls): one press on the muted speaker turns sound on; after that each press opens or closes a vertical volume flyout (`.volfly`, a rotated range input, class `.open`; drag to the bottom to mute; it also closes on an outside click or when the layer closes). There is no inline horizontal slider, so the scrubber gets the room.
- On touch, tapping the layer, the handle or the chevron pins that card as the focused one (`pinned`, in `pickFocus`) until it is wholly scrolled out of view or the page moves more than 120px, and nothing overrules it in the meantime (`touchpin_test.py`).
- **No backdrop blur on tiles unless the layer is showing.** A blur over a playing video is redrawn on every frame; one hidden layer plus badges on dozens of tiles made the page flash while scrolling through playing clips. Closed layers and the badges/buttons on a tile have `backdrop-filter:none` (a plain tint instead); only a shown layer blurs (`layer_test.py` checks it). Do not put backdrop-filter back on always-present tile elements.
- **Subreddit mode on the hosted page:** `liveHotPage` tries the relay on the page's own host (a 404 on GitHub Pages), then localhost, then reddit.com; Reddit refuses browser reads (a `TypeError`), so the archives are used. The reported reason is Reddit's own failure (`redditErr`), never the missing relay's 404. When the view is empty, `subEmptyHtml` says whether the archives returned nothing (private, banned or quarantined, misspelled, too small, or not archived yet) or which filters hid what loaded (NSFW Hide, text posts off, Hide broken media), with a button for each (`data-empty`). `subfeed_test.py`.
- **Full width** (`#fullw` button beside the Tile size slider, class `.fwbtn` (never `.fullw`: that is the body class and a button rule would restyle the body); `FULLW`, `setFullw`, `saved-posts-fullwidth`): makes the tiles **bigger**. It lifts the 1760px cap on `.wrap` and `.deck-in` (`body.fullw ... {max-width:none}`), and Tile size uses the wider grid for its steps (see Tile size below); the default is 3 across. The count is remembered apart in `saved-posts-tile-fullw`, so turning Full width off gives the normal size back. A pixel range up to one tile across was tried and spent two thirds of the bar on one or two enormous columns. No tile is taller than the window below the top bar (`capRows`, `MAXROWS`, worked out once per `relayoutAll`). The slider sets the size at most once a frame while dragging (`cardSoon`). Shown on every desktop width and hidden on phones (<=720px, which already have 3 / 2 / 1 across). The first version (one post per row) hung the browser: it read `offsetHeight` inside `layoutCard` for every card, a forced reflow per card. Never read layout values per card in `layoutCard` (`fullw_test.py`).
- **Tile size snaps to numbered steps** (Masonry and Grid; hidden in List; its label on the page says **Columns**; since Nov 2026 it runs **1 across on the left up to the most tiles on the right**): every slider position is a count of tiles across, labelled with that number under a notch, and a range with `step=1` cannot rest between two (`buildSizeControl`, `notchesFor`, `paintNotches`, `aria-valuetext` "N across"). Every screen reads the same way, 1 across on the left and most tiles on the right (`COL_STEPS`, `colCard`): phones (<=720px) get 1, 2, 3 across (counts whose tiles are at least 100px; one across stays uncapped there, as before); tablets and desktops (`sizeSteps`) run from as many 150px tiles as fit (left), **capped at 5 across (10 in Full width)** (`MAX_COLS`, `MAX_COLS_FW`, Alex's choice), down to **1 across (right, always offered)**, every count in between, so smaller windows get fewer steps. Each notch is a small dot (`.notches i::before`, filled; the lit one in ink) over its number, not an outlined tick. The chosen count is stored (`saved-posts-tile-cols`, `saved-posts-tile-fullw` in Full width, `saved-posts-tile-phonecols` on phones; an older phone index in `saved-posts-tile-phone` carries over) and snaps to the nearest step on another width; the control is rebuilt on every resize (debounced) so rotating a tablet keeps the choice. On desktop and tablets one across caps tiles to the window height (`ONE_UP`, `MAXROWS`). The old free 150–360px slider (most 10px moves changed nothing) and the tablet-only one-across stop (`ONE_STOP`) are gone (`tilesize_test.py`, `onecol_test.py`).
